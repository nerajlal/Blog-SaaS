API & Docs

Display your published posts on your own website.

1. Get your project API key

Open Projects, choose a project, then open Integration. Each project has its own read-only API key.

Open projects ↗

Keep the key in your website server’s environment and fetch content from your backend. This key never grants access to private drafts or editing.

2. Fetch published posts

Send the project key in the X-API-KEY header.

const response = await fetch("{{ request.scheme }}://{{ request.get_host }}/api/v1/projects/blogs?page=1&per_page=20", {
  headers: { "X-API-KEY": process.env.BLOGSAAS_API_KEY }
});
if (!response.ok) throw new Error("Unable to load stories");
const data = await response.json();
// data.blogs contains articles; data.meta contains pagination.

This example runs on your JavaScript server. Only published articles whose publication time has arrived are returned.

RequestPurpose
GET /api/v1/projects/blogsList published posts. Use page and per_page (1–100).
GET /api/v1/projects/blogs/{slug}Fetch one published article using its slug. Returns a post object.

3. Render on your website

Create your own listing and article routes, such as /post and /post/{slug}. Render the returned article content and sections using your frontend’s safe rendering tools. Prefix relative media URLs with this API server’s origin.

Use the returned SEO fields for page titles, descriptions, and social previews where available. Your website controls the final HTML, canonical URLs, indexing, and sitemap.

Troubleshooting

  • 401: check the project API key and X-API-KEY header.
  • 404 for a post: check its slug, project, and publication status.
  • Empty list: publish a post and check its scheduled publication time.
  • 400: check pagination values and request limits. Cache responses on your website to reduce repeated API calls.
