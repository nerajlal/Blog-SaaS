React / Next.js

Use server-rendered React pages for a public blog. The starter includes a post listing, pagination, individual post routes, images, author details, metadata and structured data.

  1. Download and extract the starter.
  2. Copy .env.example to .env.local. Set TRYWRYTER_URL to this platform’s HTTPS origin and TRYWRYTER_API_KEY to the project key above.
  3. Run the commands below and open /posts. You can also copy the routes into an existing Next.js App Router project.
npm install
npm run dev

# Production
npm run build
npm start
Download React starter

The key stays in server environment variables. For plain React browser fetches, verify your website origin in Analytics & Search → Sitemap first so CORS permits it. Browser requests expose the read-only project key. Your developer still needs to handle routes, loading/error states and SEO rendering.

WordPress

Use the downloadable shortcode plugin to show a live list and read posts inside a WordPress page.

  1. Download the plugin ZIP.
  2. In WordPress, open Plugins → Add New → Upload Plugin. Upload and activate it.
  3. Open Settings → TryWryter and enter this platform’s HTTPS URL and the project key above.
  4. Add a Shortcode block to a page and paste:
[trywryter_posts]
Download WordPress starter plugin

Fetches happen on the WordPress server, so no browser CORS setup is needed. This is an embedded reader, not native WordPress post synchronization. It does not configure per-post SEO, canonical URLs, or WordPress sitemap entries. For standalone SEO pages, choose Hosted blog, or have your developer implement native synchronization and SEO-plugin support. Disable page caching for the shortcode page or configure invalidation.

API reference & troubleshooting
GET /api/v1/projects/blogs?page=1&per_page=12
GET /api/v1/projects/blogs/your-post-slug
Header: X-API-KEY: your-project-key

Lists return blogs and pagination meta. Individual posts return blog. Use cover_image_url, section image_url, sanitized content/text_content, and the resolved seo object. Drafts and future scheduled posts are excluded.

  • 401: check the project API key.
  • 403 / browser CORS: verify the exact website origin or fetch on your server.
  • 404: check the slug and publication status.
  • Old content: check website and CDN caching after edits or unpublishing.

Use page and per_page (maximum 100). Keep AI provider keys and admin credentials out of website code.
